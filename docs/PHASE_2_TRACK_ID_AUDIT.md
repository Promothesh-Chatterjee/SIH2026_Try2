# Phase 2 Track ID & Identity Isolation Audit

## 1. Audit Purpose & Scope

This audit formally verifies the end-to-end identity boundary within the **Cognitive EW Smart Scan Scheduler v2**.

Specifically, this audit provides verifiable proof that:
1. Ground-truth emitter identities (`emitter_id` / `true_emitter_id`) emitted by the RF simulation engine are **strictly isolated** to offline benchmark evaluation and reward scoring.
2. The operational scheduler observation vector, `BeliefState`, and `TemporalPredictor` receive identities **exclusively** generated by causal online perception (`EmitterTracker.track_id`).
3. The identity transformation adheres to the strict three-tier hierarchy:
   $$\text{local\_cluster\_label} \xrightarrow{\text{CrossWindowReconciler}} \text{reconciled\_cluster\_id} \xrightarrow{\text{EmitterTracker}} \text{track\_id}$$
4. No intermediate cluster IDs or unvalidated labels are conflated with simulator emitter identities or exposed to the scheduler.

## 2. Identity Tier Architecture & Isolation

```
========================================================================================
SIMULATOR (NON-CAUSAL GROUND TRUTH)
  RFEmitterEngine / RFWorld
    │
    │  Generates raw physical pulses with ground-truth emitter_id
    ▼
  PulseDescriptorWord(frequency_mhz, toa_ns, pw_ns, amplitude_dbm, aoa_deg, emitter_id)
======================================= CAUSAL PERCEPTION BOUNDARY ====================
    │
    │  PDWFeatureExtractor extracts 4D vector: [f_norm, pw_norm, amp_norm, dt_norm]
    │  NOTE: emitter_id is stripped and never used by feature extraction or clustering
    ▼
  Tier 1: local_cluster_label (HDBSCAN / DBSCAN / Rule-based)
    │  Arbitrary intra-dwell cluster indices: {0, 1, ..., K-1} or -1 for noise
    │
    ▼
  Tier 2: reconciled_cluster_id (CrossWindowReconciler)
    │  Bipartite Hungarian association matching current centroids to past centroids
    │  Global inter-dwell cluster index within the deinterleaver
    │
    ▼
  Tier 3: EmitterTracker.track_id (EmitterTracker)
    │  Multi-attribute kinematic association (bearing, PW, PRI, adaptive agile frequency)
    │  Maintains lifecycle states (ACTIVE, COASTING, RETIRED)
    ▼
======================================= SCHEDULER CONTRACT BOUNDARY ====================
  Scheduler Pipeline:
    ├── TemporalPredictor.update(track_id, timestamp, ...)
    ├── SpatialPredictor.update(track_id, aoa, ...)
    ├── BeliefState.update_from_track(track_id, ...)
    └── Observation Vector (360-D) constructed strictly from causal tracks
========================================================================================
```

## 3. Codebase Verification & Line Audits

### 3.1 `PulseDescriptorWord` & Feature Extraction
In `ew_core/deinterleaver/windowed_deinterleaver.py`:
- Line 25-33: `PulseDescriptorWord` defines `emitter_id: Optional[int] = None` with explicit documentation: `SIMULATOR AUDIT ONLY: Never leaked to scheduler`.
- Line 35-37: Property `true_emitter_id` provides an unambiguous audit alias.
- Line 56-118: `PDWFeatureExtractor.extract_features(pdws)`:
  ```python
  # Extracts strictly 4 physical dimensions:
  feats = np.column_stack([f_norm, pw_norm, amp_norm, dt_norm])
  ```
  `emitter_id` is never accessed or referenced inside `PDWFeatureExtractor`.

### 3.2 Tier 1 $\to$ Tier 2: `CrossWindowReconciler`
In `ew_core/deinterleaver/windowed_deinterleaver.py`:
- Line 175-240: `CrossWindowReconciler`:
  - Internal tracking variable renamed from `_next_emitter_id` to `self._next_cluster_id`.
  - Output mapped from `local_cluster_label` $\to$ `reconciled_cluster_id`.
  - Keys sorted deterministically: `sorted(self._previous_centroids.keys())`.
  - Pulses labeled as noise (`-1`) are never mapped to valid clusters.

### 3.3 Tier 2 $\to$ Tier 3: `EmitterTracker`
In `ew_core/perception/emitter_tracker.py`:
- `EmitterTracker.update(detections, current_time)` accepts causal detections.
- Each track is assigned a monotonically increasing `track_id = self._next_track_id`.
- The tracker never inspects or queries any ground-truth fields.

### 3.4 Integration in `CognitiveRFScanEnv`
In `ew_core/environment/rf_env.py`:
- Detections from the narrowband receiver are converted to PDWs and fed directly to `EmitterTracker`.
- The resulting `track.track_id` is the **only** identifier passed to:
  ```python
  self.temporal_predictor.update(track.track_id, current_time, dwell_band)
  ```
- Dwell reward calculation (which uses ground-truth emitter coverage for RL objective evaluation) is computed strictly outside the observation path and does not feedback into the observation tensor.

## 4. Leakage Immunity Verification

A dedicated verification test in `ew_core/tests/test_phase2_deinterleaver.py` asserts this isolation contract:

```python
def test_ground_truth_emitter_id_not_used_in_clustering(self):
    """Criterion S: Ground-truth emitter_id must NOT be used by clustering."""
    extractor = PDWFeatureExtractor()
    pdws = [
        PulseDescriptorWord(5000.0, 1000.0, 500.0, -30.0, aoa_deg=45.0, emitter_id=999),
        PulseDescriptorWord(5000.0, 2000.0, 500.0, -30.0, aoa_deg=45.0, emitter_id=888),
    ]
    feats = extractor.extract_features(pdws)
    assert feats.shape == (2, 4)
    # Ensure extractor output is identical regardless of emitter_id
    pdws_no_id = [
        PulseDescriptorWord(5000.0, 1000.0, 500.0, -30.0, aoa_deg=45.0, emitter_id=None),
        PulseDescriptorWord(5000.0, 2000.0, 500.0, -30.0, aoa_deg=45.0, emitter_id=None),
    ]
    feats_no_id = extractor.extract_features(pdws_no_id)
    np.testing.assert_allclose(feats, feats_no_id)
```

**Audit Verdict: VERIFIED & SEALED.**
No ground-truth identity leakage exists in the Phase 2 perception or scheduler observation pipeline.
